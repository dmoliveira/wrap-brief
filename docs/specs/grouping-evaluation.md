# Grouping evaluation and reviewed overrides (partial T05.03)

Status: implemented offline APIs; no real-event benchmark qualification yet. The current repository has no rights-safe independently labeled real-event corpus. Fictional fixtures can validate measurement and replay, **not** complete T05.03.1/.2, the ≥100-real-pair/≥98% observed precision gate, or the parent task. No source activation or live fetching is required merely to supply an authorized offline corpus; that corpus is currently unavailable.

## Scope and validation

This slice is pure grouping/evaluation and bounded configuration parsing, with no network, storage writer, new dependency, workflow, renderer bridge or numeric-threshold tuning. It adds a narrow fuzzy-disable policy, a reviewed override adapter and reusable full-batch measurement. Known-event default behavior remains unchanged. One post-measurement safety amendment requires canonical-URI equality for automatic `other`-event matching: identical generic headlines do not establish event identity when the classifier has no event constraint. Existing semantic/time/claim/number/edition/quoted-entity guards still precede URI equality. This deliberately sacrifices additional unknown-event recall; explicit reviewed overrides remain available. It does not address all known-event ambiguity or prove general accuracy.

Medium risk: plan review and final implementation/release review, plus independent verification. The design review required mixed-event lead semantics and prior-membership validation before filtering; a separate narrow oracle decision approved the measured ambiguity amendment without changing labels or numeric thresholds.

## Fuzzy disable

`group_items(..., fuzzy_enabled=True)` retains the current default. Only a strict boolean is accepted. When disabled, semantic/time/claim/number/edition/quoted-entity guards still apply, but title similarity cannot group different canonical URIs. The flag applies to **previous-group placement as well as new matching**; old fuzzy groups cannot silently survive the switch. Exact identity normalization/replay is a separate unchanged stage; no Item, URL or alternate coverage is deleted by this switch. Explicit reviewed manual decisions remain separate from automatic fuzzy behavior.

## Current reviewed override plan

`GroupingPlan` is separately supplied current reviewed application input: version 1, ID, positive revision, explicit UTC review time and bounded current decisions. A `GroupingDecision` has a stable ID, merge/split/release action, explicit immutable targets `(source_id, item_id, metadata_ref)`, split partitions where applicable, review time and explicitly reviewed public evidence reference. Merge requires at least two intended targets and no partitions; split requires at least two complete disjoint partitions of at least two targets; release requires at least one target and no partitions. Targets cannot overlap between decisions. Unknown fields, duplicate keys/IDs, malformed counts, nonfinite values and conflicts fail closed. Plan JSON is capped at 1 MiB, 1,000 decisions, 100 targets/decision and 10,000 targets total.

Grouping metadata references use a versioned domain, NUL and canonical sorted-key UTF-8 JSON including Item ID/source/title/URL/GUID/publication/update/claim status with explicit nulls and normalized UTC. Observation clocks and availability status are excluded: **status-only** withdrawal demotes an unavailable lead without invalidating a grouping review; any bound publisher/claim metadata change still requires new review. A present target must match source ownership and its metadata reference. Review cannot predate known bound publisher times; decision review ≤ plan review ≤ supplied application time. Input observation clocks must not be in the future.

Review references are public-safe citations chosen explicitly by the reviewer; syntax does not authenticate or approve them, and no reference is fetched. Hashes, revisions, timestamps, Python types or an `approved` flag are not authority. The trusted application must select/retain the current plan and every effective obligation. Reversal requires a reviewed replacement or explicit `release`, not quietly forgetting a decision. This component cannot authenticate a stale/edited replacement plan. Real runtime plans and publisher metadata stay private/untracked; `config/overrides/` contains only empty/synthetic examples.

## Adapter and replay semantics

`group_with_overrides` validates current Sources/Items/clocks and exactly one trusted LeadEvidence per Item before indexing. It validates **unique previous cluster IDs and nonoverlapping retained current membership across every previous group before filtering**, including manual groups and targets that will be locked. Expired members need not exist. This prevents overlap from disappearing behind target filtering.

Present merge/split targets are locked out of automatic grouping; only explicitly reviewed current members enter their fixed buckets. Missing targets stay dormant and reapply on unchanged resurfacing. New/unknown members never inherit a decision through a cluster ID. A missing target does not erase a supplied record or cancel other partitions. Metadata/source conflicts fail rather than silently fall back to fuzzy matching.

Prior manual groups are not blindly downgraded: every retained current member must be covered by the current reviewed plan, including an explicit release where appropriate. Manual prior groups are never forwarded to the automatic grouper. Automatic prior context is filtered to unlocked present members, empty groups dropped and lead context sanitized. Released targets return to fresh automatic grouping. The result is a complete deterministic partition of all supplied Item IDs, without rewriting claims, statuses, provenance or URLs.

Manual groups use opaque generated IDs and `confidence=manual` with the explicitly public review reference. Recompute lead and derived labels from current records and supplied trusted lead evidence. A common classified event is used only when all members agree; a heterogeneous manual merge uses **other**, so it receives no primary-event preference. Claim/correction status remains derived from the eligible current lead and members. Grouping authority does not establish confirmation, lift withdrawal, or override upstream erasure/source exclusion.

The editorial boundary deliberately continues to reject raw manual confidence/override metadata. This slice supplies no integration bridge, no stripping of provenance to evade `ControlledBatch.finish`, and no change to canonical editorial IDs. Any later bridge must validate both current ledgers against controlled inventory and receive a separate review. The existing CLI does not automatically load/apply a grouping plan.

## Exhaustive batch measurement

The pure evaluator accepts bounded reviewed `GoldScenario` inputs with validated records, explicit clock/lead evidence, category, rationale/public label reference and a complete gold partition. At most 50 Items/scenario, 50 scenarios, 10,000 scored pairs and 4 MiB canonical corpus bytes are supported. Item IDs cannot be reused across scenarios to inflate distinct-pair counts. It runs actual default `group_items` on each **complete mixed batch**, with no manual overrides. Every within-scenario unordered pair is scored from final co-membership, including collateral false merges; disconnected cross-scenario negatives do not inflate the sample. Gold partitions provide exhaustive consistent labels rather than cherry-picked pair lists.

Report TP/FP/FN/TN, scored pair and scenario counts, positive/negative/predicted-merge denominators, precision/recall and category breakdowns. No predicted merges means undefined precision and a failed numeric target, never 100%. The numeric target is ≥100 distinct within-scenario pairs and ≥98% observed precision with a nonzero predicted-merge denominator. It is **not a corpus/rights/independent-label approval** or a population accuracy guarantee. Correlated pairs are not independent statistical trials; no unwarranted confidence claim is made. False-merge identities remain a private diagnostic API; default public summaries contain only bounded fixed-category aggregates, never headlines, URLs, source/item/scenario IDs or paths.

The committed synthetic corpus is explicitly fictional and frozen as test data before measurement. It covers mixed Direct announcements, same-game event differences, reviews/previews, localization, rumor/confirmation, syndication, resurfacing, tracking, corrections and edition/version boundaries. Labels/rationales are test semantics, not claims of independently adjudicated real publisher events. Synthetic scores exercise the evaluator and are not used to tune the default similarity threshold. A fixed-input developer helper may print aggregate synthetic results; it is not the real `grouping-gold-benchmark` gate.

`make benchmark-fixture` invokes the fixed-input measurement helper, not a gold approval check. Successful execution means the measurement completed; inspect `numeric_target_met` and `real_corpus_qualification`. The first unchanged-fixture result was TP 0 / FP 1 / FN 48 / TN 71 (one ambiguous false merge; precision/recall both zero). After the finding-driven unknown-event guard, the same 120 pairs measured TP 0 / FP 0 / FN 48 / TN 72: **no predicted merges, precision undefined, recall zero, numeric target false**. This is regression evidence after a policy change, not independent validation of that change or a passing benchmark. Neither labels nor the 0.85 threshold were changed to conceal results. Paraphrase/localization recall remains unproven and poor on this deliberately hard fictional sample.
