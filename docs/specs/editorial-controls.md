# Reviewed editorial boundary (T05.04)

Status: implemented standalone APIs; verification/release evidence remains required for completion. This component adds attributed evidence and correction/removal controls, not original briefs, live collection, publisher permission or a storage provider.

## Authority and current ledger

The application supplies a **current, independently reviewed `ControlLedger`**, separately from candidate/feed/Snapshot data. A serialized ledger, revision number, timestamp, hash, public-reference syntax or Python type does not authenticate its reviewer or authority. There is no `reviewed: true` escape hatch. No evidence URL is fetched. Source configuration and attribution also remain separately trusted application input; Snapshot approval fields do not authenticate them.

A replacement ledger must carry every still-effective correction, retraction, erasure and source-exclusion obligation. Omission is **not reactivation or cancellation of a correction**; an older active Snapshot with identical metadata still needs its correction acknowledgement. This means retaining current obligations, not append-only article history. This pure component cannot detect substitution of a stale/edited ledger, enforce private retention terms, or select the latest provider version. The trusted caller must retain the current ledger outside candidates, reapply it after polling and before rendering, persistence or restoration, and refuse publication when it is unavailable. Raw SQLite CAS checks only revision integrity, not semantic non-resurrection.

The single state entry point accepts a validated **`Snapshot` only**, not an unchecked `PollBatch`. After supplied-result reduction, callers construct an interim Snapshot from the batch's validated sources/items/checkpoints/tombstones and explicit observation time; its clusters can be empty. They separately preserve and enforce the reducer's current health guard. Controls return no original Snapshot, PollBatch, deleted Item or hidden historical object. This deliberately avoids adding another raw-outcome validator or changing the pipeline CLI.

## Version-1 records and evidence binding

- **ClaimEvidence:** stable review ID, source ID, item ID, `reported`/`confirmed`/`rumor`, metadata reference, explicit UTC review time and explicitly reviewed public evidence reference. Every displayable Item requires one exact current record. Its claim label is derived from that evidence, never the incoming claim flag. Missing/stale evidence fails closed; there is no implicit reported fallback.
- **CorrectionControl:** stable review ID, source ID, optional item ID, action, explicit UTC review time, optional metadata reference and optional explicitly reviewed public notice reference. `correct` requires a non-null item ID, Item metadata reference and public notice reference; `retract` requires an item and public notice reference; `erase_item` requires only item/source identity and time, without public notice; `exclude_source` has no item/public notice. Metadata references are forbidden for every action except `correct`.
- **ControlLedger:** ID, positive revision, explicit UTC review time and bounded immutable current claim/control tuples. One claim per item and one effective control per target; IDs/targets/conflicts are checked. Excluded sources cannot retain accompanying per-item claims or controls. Erased items cannot retain claim metadata. Absent targets can remain as dormant suppression obligations; matched Item/tombstone identities must have the same source.

Canonical references use SHA-256 with separate `wrap-brief:claim-metadata:v1` and `wrap-brief:editorial-ledger:v1` domains followed by a NUL and canonical JSON: sorted object keys, compact separators, UTF-8, no nonfinite numbers. Claim metadata includes explicit nulls and normalized UTC for Item ID/source/title/URL/GUID/publication/update fields. Observation-only first/last-seen clocks and mutable claim/status flags are excluded. A changed title, URL, GUID or publisher timestamp requires fresh evidence; ordinary observation changes do not. Only metadata-bound ClaimEvidence and `correct` reviews must be no earlier than known publisher timestamps. Sticky retract/erase/exclude reviews may predate later publisher changes. References establish consistency, not authority or publisher reuse rights.

The ledger is capped at 1 MiB and 1,000 claims/controls each. Strict JSON rejects unknown/duplicate keys and nonfinite values. Review times must be no later than the ledger's review, which must be no later than the supplied application time. Input observation cannot be after that time. Snapshot size/type/ownership/URL/clock limits remain in force; output serialization is bounded before return.

Public references are explicit reviewed citations, not private correspondence or original article content. They may be query-free public HTTPS or a narrow `content/corrections/<slug>.md` reference (optional simple fragment). Syntax alone cannot detect private or withdrawn text in a path; the reviewer must select a publication-safe reference. Render them as escaped reference text, not invented working links or fetched evidence.

## Transformation, regrouping and rendering

`apply_controls(snapshot, *, ledger, observed_at)` produces only the controlled current state plus sanitized prior grouping context. `correct` binds current metadata and never lifts retracted/removed/quarantined state; an inherited corrected Item must also have matching current correction provenance. Retraction is sticky across later metadata changes. Erasure removes the full Item and uses the existing minimal item/source/time Tombstone, including when an old Snapshot lacks that tombstone. If even item-level suppression cannot be retained under source-specific terms, use source-wide exclusion instead of promising item-level non-resurrection.

Source exclusion suppresses all present and future IDs for that source, disables its Source, and drops its Items, checkpoints and tombstones. Only source-level suppression remains. Removing a record means removing its memberships and empty prior groups too; recompute retained prior-group topics/labels without carrying arbitrary old topic/override text. The source's separately reviewed public registry/attribution configuration is not a private article archive. No permission or retention period is invented.

The caller explicitly invokes `group_items` on the returned inventory with fresh trusted lead evidence and sanitized prior groups. `finish(clusters=...)` requires a complete nonoverlapping partition, valid available leads and truthful derived correction/claim labels, including the existing grouper's title-derived rumor caution. A quarantined-only group does not become a public retraction notice merely because grouping marks an unavailable group withdrawn.

Public editorial group IDs cannot carry historical identifiers or erased text. Every returned prior group is rebound to `editorial-group-v1-` plus SHA-256 of `wrap-brief:editorial-group:v1`, NUL and canonical JSON `{"member_ids": <sorted current IDs>}`. The original group ID and erased membership never enter that reference. `finish` first validates the complete supplied partition/topics/overrides/labels, then rebinds final IDs; direct result construction/validation requires exact derived-ID equality, not merely a hexadecimal prefix. Duplicate derived IDs fail rather than receive raw-input suffixes. Item IDs are unchanged except for explicit erasure. This new boundary preserves anchors for identical membership, including reordered input, **not across membership changes**; raw grouping/legacy CLI policies are unchanged. Opaque references are not general anonymity or arbitrary-content redaction.

`EditorialResult` binds its current Snapshot to its supplied ledger, revalidates controls and grouping, and derives notices rather than accepting an arbitrary notice list. `render_editorial(result)` uses the existing synthetic/reserved-host/no-JS renderer and preserves its total HTML limit. Existing `render_digest` and CLI fixture contracts stay unchanged; they are not silently upgraded to a production editorial admission gate.

Public editorial records use fixed labels, review times and explicitly reviewed public references, never original-brief text, correspondence, internal review IDs, erased titles/URLs or raw evidence payloads. Claim/correction records refer only to present displayable targets; absent/unmatched corrections produce no correction notice. A durable retraction may have a generic global trace with no withdrawn title/link/target text. The final partition rejects arbitrary topics and overrides as well as stale memberships/labels, so a caller cannot reinsert erased text in cluster metadata. Erasure and source exclusion produce no per-item public notice. HTTPS/reference syntax is not proof that publication is authorized.

## Removal report and real owned-sandbox exercise

`removal.py` is a **pure report contract, not a deletion tool**. It requires exactly eight unique categories: private records, exports, backups, public HTML, JSON, RSS, deployment artifacts and owned caches. Each has strict nonnegative counts, fixed `removed`/`not_configured`/`pending`/`failed` status, explicit UTC check time and a reviewed public evidence reference. `removed` requires an observed match before and none remaining; `not_configured` means absent, not erased. Missing categories, pending or failed outcomes cannot resolve the declared scope. A report is an operator assertion, not physical/provider erasure proof; it never promises external-copy deletion.

Tests will create only a **new owned synthetic sandbox**, prove withdrawn content exists in each named category, apply controls, remove/rebuild explicitly inventoried owned copies and inspect actual database/files/sidecars. Unrelated owned content must survive. The exercise includes LocalState restart, reloading the current external ledger, identical/changed polling, and restoration of an old Snapshot using current CAS through controls. A separate negative demonstration records that raw `LocalState.commit(old_snapshot, current_revision)` can resurrect data; the editorial boundary, not CAS, prevents that path when used correctly.

Failure/pending and genuinely unconfigured surfaces remain explicit. Synthetic JSON/RSS and artifact/cache copies are drill fixtures, not product feeds or hosted deletion. Physical tests do not prove SSD/provider forensic erasure, mirrors, hosted artifact invalidation, or production durability. Accidental publication to Git is an incident under SECURITY.md, never an archival or removal strategy.

Required acceptance checks: **editorial-provenance**, **correction-takedown-drill**; high-risk design/implementation/release reviews, supported-version suites, wheel smoke, existing nine-artifact scan and an explicit scanner pass over the new editorial output. Live publisher approval, provider integration, hosted removal and actual assistive-technology evidence remain separate gates.

The named checks execute in `tests/editorial/test_controls.py` and `tests/editorial/test_removal.py`. The latter's explicit new-output scanner case requires `WRAP_BRIEF_GITLEAKS` pointing to the checksum-verified executable; ordinary offline runs skip it rather than claim a scan. An external Playwright installation can run `node tests/editorial/check_editorial_browser.cjs` with `NODE_PATH` and optional `BROWSER_EXECUTABLE`; it builds its own newly owned synthetic fixtures and cleans up only those. No browser package joins the product lock. Its no-JS/keyboard/reflow checks and long-reference stress do not replace actual assistive-technology testing.
