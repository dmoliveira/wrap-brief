# T03.01 — bounded one-source HTTP client

Scope: serial approved-source HTTP boundary, validated/pinned DNS destination with verified TLS, process-isolated single-hop operation, streaming encoded/decoded limits, conditional requests and shared redirect/retry/backoff budgets. No live source, publisher request, collection schedule, parser integration, persistence provider, successful-checkpoint write or deployment is activated. The registry remains empty.

Pre-implementation architecture review rejected DNS-only timeouts and injection-only completion. The accepted design isolates the full DNS/TCP/TLS/HTTP hop, preserves TLS hostname verification/SNI while pinning numeric destinations, bounds trusted worker protocol/body/header metadata, kills/reaps on timeout/cancellation and keeps retry/redirect/poll policies in the parent. OS process creation/reap timing and trusted-output capture caveats are explicit in `docs/specs/feed-http.md`; no OS-sandbox or exact-return-time claim is made.

Initial security review found that Retry-After could be lost on the final transient response after retry exhaustion. The fix preserves terminal numeric/date delay without another request, including a fail-closed deferred result for invalid server delays. Independent release review additionally found the same loss when response processing crossed the total deadline; parsing now precedes that exit too. Focused regressions cover exhausted retries and deadline-boundary 429/503, asserting the requested remaining delay without another request. Both scoped follow-up reviews approved the repairs with no remaining high/medium findings. A literal empty redirect fragment regression also prevents URL joining from erasing a prohibited `#`.

Independent final verification passed **237 tests on both Python 3.11 and 3.13** with ResourceWarnings treated as errors, including 25 HTTP tests, lock/plan checks, Ruff lint/format and whitespace checks. It also passed 52 standalone planning tests and the isolated wheel installation/import/worker smoke outside the checkout. Tests use shared synthetic transport examples and richer deterministic fake sequences; fake DNS/sockets/TLS and real stdlib HTTP parsing over synthetic chunked/gzip byte streams; no publisher network requests. DNS tests include mixed/private/multicast/mapped/transition destinations and the Azure platform virtual address. A real sleeping subprocess proves timeout termination/reap without networking. The isolated installed-worker wheel smoke rejects invalid input before DNS. This component cannot clear source-permission, private-state or real-screen-reader blockers.
