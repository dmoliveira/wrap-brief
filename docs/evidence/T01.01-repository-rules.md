Scope: contributor/ownership guidance, issue/PR templates, accurate private security reporting and live protection evidence. No application runtime, workflow event/permission, source, provider, deployment or licensing change is introduced. The existing main rules and reporting route were inspected, not silently weakened or replaced.

Pre-experiment security review approved a unique owned protected sandbox with exact-ref non-force push and mandatory cleanup; no write attempt to `main`. It also required truthful zero-peer-approval disclosure and a clear distinction between static fork-policy evidence and an actual cross-account fork drill.

Observed repository settings: public repository, protected `main` requiring PRs/current `Planning checks` bound to GitHub Actions app 15368, strict status enforcement and administrators included; force pushes/deletion disabled. Independent approving reviews are **not** platform-mandatory (count 0) and required code-owner review is off. Default workflow token is read-only and cannot approve PR reviews. Private vulnerability reporting, secret scanning and push protection are enabled. No account billing or private contact details are included here.

## Executed protected-branch sandbox

The unique temporary `sandbox/T01.01-7d9e876c32` ref was created at `0f668ed5d6ed7234a09ae845647fcf10443b488d`, protected with required PR, strict app-bound `Planning checks` and administrator enforcement, and read back before testing. This is platform rejection evidence, not an authentication or network failure.

The experiment then removed only its own sandbox protection and ref, verified the ref was absent, and compared main protection before/after: **unchanged**. `main` was never a direct-push target. The candidate and captured diagnostics contain no publisher data or credentials; raw logs/private tool context are not publication artifacts.
