# T03.04 — incremental poll state and honest source health

Scope: pure supplied-result reducer over complete retained state, safe parse/normalize/identity/replay, per-source checkpoint transitions, 304 handling, last-good fallback, possible-window warnings and an all-source-failure health guard. No HTTP request, clock lookup, scheduler, provider, source activation, persistence side effect, renderer or publication workflow is introduced.

Pre-code architecture review required an exact result matrix, explicit expected-source denominator, unchanged 304 record clocks/window, quarantine-only versus truly empty semantics, validator replacement/retention, state count/byte bounds and a mandatory explicit grouping handoff. The reducer returns a PollBatch, not an implicitly renderable Snapshot; explicit current groups and serialized bounds are required before persistence. Restart-safe retry deadlines/holds and warning histories are not falsely claimed from the unchanged checkpoint schema.

Initial state/security review found that normalizer defaults could clear stored quarantine/correction/claim state on a successful refresh. The polling boundary now retains prior nonactive restrictions and explicit rumor state, preserves confirmation for unchanged publisher metadata, and retains the changed-content confirmation downgrade/regroup behavior. Unchanged and changed replay regressions check lead availability and correction/claim labels. The scoped follow-up approved the repair without remaining findings.

Independent release review additionally found a source-isolation gap: a newly supplied publication date could conflict with retained update metadata and abort the whole batch. Only that fixed core chronology rejection now becomes a source-local `metadata_conflict`; identity/integrity and size errors remain fatal. Two-source last-good/degraded and fatal-identity regressions pass, and the scoped follow-up approved the repair.

Independent verification passed `make help`, `make validate`, strict-ResourceWarning full suites on **Python 3.11.15 and 3.13.14 (269 tests each)**, `make test-wheel`, `make test-plan PYTHON=python3` (**52 planning tests**) and `git diff --check`, including untracked candidate files. The full suite includes 29 new polling tests and 240 existing tests; locked Ruff lint/format and lock/plan checks passed. Wheel checks exercised the installed reducer and isolated HTTP worker outside the checkout.

Cases include physical/accepted/quarantined/duplicate counts, exact same-clock replay, content versus observation updates, 200/304 validators, unsolicited 304, mixed/all quarantine, empty RSS/Atom, source outages/deferrals, last-good retention, strict gap boundaries/shrinkage/saturation/unknown dates, tombstones, safety flags, malformed result/clock/source contracts, grouping/serialized-size/record limits and local CAS restart persistence through injected conditional HTTP/304. No publisher was contacted; the local database is synthetic/private temporary state only.

Publication checks: checksum-verified Gitleaks 8.24.3 found no credentials in the exact staged full tree or all 15 existing commits. Manual staged/ignored-file inspection and private-marker checks found no runtime databases, private tool state, logs or machine paths in tracked content; commit identities use the public noreply address.

Architecture, implementation/state-safety and independent release reviews are complete, with both scoped repairs approved and no remaining high/medium findings.
