# Reviewed grouping plan examples

Only empty/hand-authored synthetic examples belong here. `empty.json` is an inert version-1 example, not a current production review or source permission. The CLI does not load it automatically. Real current grouping ledgers and publisher metadata remain private/untracked.

## Synthetic

A reviewer supplies explicit source/item/metadata targets and public-safe evidence references. Merge/split/release decisions never establish claim confirmation, change availability or delete source records. Missing targets remain dormant; a changed bound claim needs new review. Observation and status-only withdrawal do not invalidate the grouping reference.

Dropping an effective decision is not a reversal. Retain current obligations or issue a reviewed replacement/explicit release. Hashes, counters, timestamps, an `approved` flag and Python types do not authenticate review; the application must choose the current trusted plan.

Raw manual groups are not accepted by the standalone editorial boundary. Stripping manual confidence or override references is not a valid integration bridge. See [the contract](../../docs/specs/grouping-evaluation.md).
